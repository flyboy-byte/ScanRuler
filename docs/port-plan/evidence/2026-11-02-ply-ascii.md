## Implemented body and comparison

`parsePLY` raw signature/header search, declaration processing, format/refusal
order and winding comment are ported for ASCII. `parseAsciiBody` runs to its
complete return: vertex allocation and property ordering, unknown/list-property
skips, repeated elements, original numeric prefixes, face aliases and triangle
fans, Float32 stores and final Uint32 conversion. Ignored source normals/colors
are not fabricated in Rust. No graph validation, scaling or welding is hidden
inside the file parser.

The 60-case corpus retains all initial 56 inputs and adds four cases for repeated
and negative-count elements and missing format. Seeds remain 1,7,99,1039. The
original and Rust execute on independent copies of the input; no source output
enters Rust. **46 complete outputs / 14 exact source refusals** pass. Comparisons
cover every float32/index byte, indexed kind, counts and optional winding state,
plus complete progress and refusal UTF-8. There is no numerical tolerance or NaN
normalization. A deliberately changed coordinate bit and a missing output word
are rejected against the actual original triangle output.

`2026-11-02-ply-ascii-cases.json` retains identities, original/Rust full output
hex, progress/error hex, input/output hashes and sizes. Input bytes are committed
under `fixtures/ply-ascii/`; its manifest/generator and fast-gate test prevent
silently missing or changed inputs and compiled schedule. Raw failed outputs are
written before assertions. The original adapter reads the pinned Git object and
uses the original locked TypeScript dev dependency only to erase annotations;
no formula is replaced. Native CI installs the unchanged original lock for this
reference-only adapter; there are no new npm or Cargo dependencies.

The native oracle discovery guard and raw artifact roster now require this suite
in addition to every previous suite. Existing STL UTF-8, whitespace and numeric
prefix helpers are reused with visibility-only changes, not duplicated or retuned.

## Explicit limits and missing continuation

Byte, vertex, output-triangle and property/work budgets are caller-specified.
Storage is owned and reserved fallibly. Negative vertex allocation has the source
refusal; negative/NaN counts and cursors otherwise retain the source's successful
observable behavior. Malformed inputs producing NaN coordinates or wrapped/zero
indices are not silently repaired. Safe downstream graph validation remains
separate. Giant declared workloads are tested against Rust host guards rather
than allowed to hang or allocate unbounded storage in the reference.

Recognized binary encodings reach `BinaryNotPorted` exactly at the missing body
call boundary. Both byte orders remain tracked under `io.ply.binary`; this is not
a claim that PLY import is complete. Native and Wasm compilation plus ordinary
host-guard tests pass; actual browser-Wasm parser comparison, engine scan commands,
history and the wider P03 corpus remain open. No acceptance promotion is made.
