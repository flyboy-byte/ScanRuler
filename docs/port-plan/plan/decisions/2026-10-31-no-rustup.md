# Decision: 2026-10-31-no-rustup

- Affected units, contracts and active contributions: P00 (toolchain), P39 (xtask), all Rust units.
- Existing plan/behavior: HANDOFF step 3 asks for "a pinned stable Rust toolchain with native and wasm32 targets".
- Proposed change and reason: use the distribution toolchain (Arch `rust` 1.99.1, which already ships `wasm32-unknown-unknown`) and record its exact versions with `cargo xtask env`. Do not install `rustup`.
- Evidence, reproduction and tested commits: on Arch the `rustup` package declares `Conflicts With: rust cargo rustfmt`, so installing it removes the working toolchain (`pacman -Si rustup`). `cargo xtask ci` passes on the distribution toolchain, including `cargo check --target wasm32-unknown-unknown` (workspace scaffold, 2026-10-31). No document in this packet requires rustup or nightly (searched for `nightly`, `rustup`, `toolchain`, `msrv`). `~/solidcore` documents the same situation: "Without rustup, allow those lints".
- Alternatives and compatibility impact: a `rust-toolchain.toml` pin only works with rustup. CI (GitHub's runner image) has rustup, so CI can pin; local contributors on other systems may use rustup. The workspace declares `rust-version = "1.88"` as the floor. Newer local clippy may add lints that older CI does not know; treat such lints as local noise unless CI shows them.
- Required tests/migrations and follow-up units: none. If CI pins a version, add `rust-toolchain.toml` then and record why.
- Owner/reviewer decision and date: Logan, 2026-10-31 ("rustup uninstalls the current setup ... I don't believe it's required"); verified by the session.
