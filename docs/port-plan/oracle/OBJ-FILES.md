# Companion file selection and bytes contract

Specified 2026-11-02 before Rust implementation, io.obj.companions.files.
Execute full pinned formats.ts and the complete scanFiles.ts module; only imports
are bound to pinned formats and the original installed fflate reference dependency.
Never call image decoding or stub a reached continuation. File inputs are authored
names/bytes with independent object identities, not original results.

Compare FLS1 exact bytes for extension/classifiers and all picker constants;
stateful bundle selection, companionsOf for every input identity after each step,
and complete companionBytes names/data/order. Same-name files remain distinct;
repeated references stay repeated; first model wins; non-textures are ignored;
without a model use first file; an empty/new untextured bundle does not clear
an earlier association. Byte snapshots never mutate input or associations.

Valid UTF-8 names are the explicit boundary; no path stripping/trim/normalization.
Source extensions lower the whole last dot-separated segment, including no-dot
names. Classifier/registry constants are included in every format observation.
Four seeds (1,7,99,1039), fixed IDs/hashes and full original capture precede Rust.
No numerical tolerance or seed trimming. Resource/invalid-ID/allocation failures
are host errors, not source refusals. IDs live only within one owned ingress set;
this is not a session/history/command identity system. No file deletion/reuse API.

Dropped directory traversal, async platform I/O/rejection/timing, image decoding,
3MF packed companions, public import/project integration and broader filename
interoperability remain open. Each ported function is complete for this owned
byte input boundary; omitted functions are not counted as implementations.
