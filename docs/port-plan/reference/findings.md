# Source review findings and provenance

Reviewed baseline: `flyboy-byte/ScanRuler@2cd89c6769a10c27ee7754b477ada521c9ef5cb7`, 2026-10-31. Selective review for a standalone AGPL port. This is source-informed work. The full repo was not cloned or executed.

1. `src/headless/engine.ts`: one engine per process through module state; implements an in-thread worker shim and filters commands using a `headless` flag. Scan/page commands are refused. `mcp/src/engine.js` dynamically loads the built Node engine rather than speaking an external Rust protocol.
2. `src/core/types.ts`, `src/core/geometry/buildGraph.ts`: packed f32 mesh positions/normals; u32 indexed triangles and CSR adjacency. Import welding/filtering/normal orientation determine ID/selection behavior. `src/core/deviation/rigid.ts`: row-major f64 poses, column-major render conversion, f32 point baking and reorthonormalization.
3. `src/commands/types.ts`/`registry.ts`: twelve named error codes; independent mutation and scene queues; interrupting stops, deferred settling, recent outcomes and 10-minute default timeout. Timeout documentation permits partial mutation. Rust atomicity is a design choice, not observed upstream behavior.
4. `mcp/src/commands.json`: 72 stored core descriptors; no reverse or mesh namespace. `plugins/reverse/app/reCommands.ts` registers 49 entries, with a separately enumerated headless set; `plugins/mesh-tools/app/meshCommands.ts` registers 19. Static reconstruction gives 140 candidate names; full runtime descriptors/flags remain uncaptured.
5. `src/core/project/manifest.ts`: root schema 1, legacy app marker ScanRuler, optional legacy defaults; recipes rather than all derived maps. `archive.ts`: 16 members, 64 MiB manifest, 1 GiB expanded-total limits and duplicate/invalid member checks. `src/app/projectSections.ts`: unowned plugin data/members survive load/save without that plugin, and sections prepare before restore.
6. `plugins/reverse/app/projectSection.ts`: independent part version 3; version 2 changes circular pattern semantics, version 3 changes mirror body identity. STEP imports are bundled in a plugin archive member. Legacy move-face data may hold one face rather than a face list.
7. `plugins/reverse/core/features.ts`: 27 FeatureFlags-derived feature interfaces. Face/edge picks are fingerprints, not merely indices; body/island IDs and pattern semantics require care. `buildTypes.ts` alone was insufficient to extract the feature list, since it mainly contains resolved builder/report types.
8. `plugins/reverse/core/kernelTypes.ts` and `kernel.ts`: opaque shape arena, release ownership, face history/hash descriptors, profile loops and labelled STEP parts; wrapper includes higher-level logic, not only direct package calls. A native backend must preserve relevant behavior and persistent picking, not raw hash values.
9. `plugins/mesh-tools/core/manifold.ts`: JS dynamic loader plus separate Wasm asset and retry after failed load. `src/core/parsers/step.ts`: meshstep conversion reports tessellation deviation, units, unsoundness and missing geometry; preserve those qualifications in inspection output.
10. `.github/workflows/ci.yml`: root and MCP packages tested separately, plugin boundary/display-unit checks, production build and selected browser runner. `scripts/e2e-ci.mjs` runs six core dev-server suites plus plugin ci.json entries and production smoke. Not every browser script is selected.
11. `.github/workflows/license-check.yml`: checks both dependency trees with an explicit allowlist and exact meshstep exemption. Additional dependencies require actual license/build inspection, not merely finding a Rust crate with a matching name.
12. `src/plugins/api.ts`: plugin extension points reach commands, history, project state, workers, scene layers and platform UI. It is not a stable binary ABI that can simply be reused between TS and Rust.

The accompanying `source-review.json` gives immutable URLs and original Git blob IDs. It lists reviewed files, not all implementation files. For continuation, read exact source at those references or obtain the full pinned checkout. `core-commands.json` is a source-derived descriptor snapshot; preserve upstream license and attribution. No source snippet has been installed into a Tangency project.
